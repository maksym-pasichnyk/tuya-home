# Tuya Home

A Home Assistant custom integration for controlling Tuya Wi-Fi devices **over the local network only**. It needs no Tuya cloud connection while running, no `tinytuya`, and no third-party Python dependencies. The only library it uses is `cryptography`, which already ships with Home Assistant.

## Features

- **Protocols 3.3, 3.4 and 3.5**, including session-key negotiation (3.4/3.5) and AES-GCM (3.5).
- **Automatic discovery.** The integration finds devices on its own by passively listening to Tuya UDP broadcasts on ports 6666, 6667 and 7000; it never sends anything to discover them. If a device gets a new IP from DHCP, the integration finds it again by its Device ID, so you don't need address reservations.
- **Local push.** The integration keeps a persistent connection with heartbeats. State changes arrive instantly without polling, and the connection is re-established automatically if it drops.
- **UI setup.** Pick a discovered device and enter its local key.
- **Entities:**
  - switches for boolean DPs `1`–`6`;
  - current, power and voltage sensors for DPs `18`/`19`/`20` on metering plugs.

## Installation

### HACS

1. Open **HACS → ⋮ → Custom repositories**.
2. Add this repository's URL with the type **Integration**.
3. Find **Tuya Home** in HACS and click **Download**.
4. Restart Home Assistant.

### Manual

1. Copy `custom_components/tuya_home` into `<config>/custom_components/`.
2. Restart Home Assistant.

## Setup

1. Go to **Settings → Devices & Services → Add Integration → Tuya Home**.
2. Wait a few seconds while the integration listens for broadcasts.
3. Pick a device from the list, or choose **Enter manually**.
4. Enter a name and the device's **local key**.

### Getting the local key

The local key is generated by the Tuya cloud when a device is paired, so you need to fetch it from the cloud once:

1. Create a cloud project on [platform.tuya.com](https://platform.tuya.com).
2. Link your Tuya Smart / Smart Life app account to the project (**Devices → Link App Account**).
3. Open **API Explorer** and call **Query Device Details** (`GET /v2.0/cloud/thing/{device_id}`).
4. Copy the `local_key` field from the response.

The key stays valid as long as the device is not removed from the app and re-paired. You can block the devices' internet access on your router afterwards, and local control keeps working.

## Limitations

- Only switch DPs `1`–`6` and metering DPs `18`/`19`/`20` are exposed. Other DPs (timers, schedules, relay behaviour after power loss) are ignored.
